# wakecron Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build `wakecron`, a macOS CLI that wakes the Mac with one-time `pmset` events and runs scripts from `scripts/` through per-job launchd LaunchAgents.

**Architecture:** Pure modules (`schedule`, `plist`, `sudoers`) hold all date and format logic. A context object from `paths.js` carries file locations, tool paths, the clock and IO into the I/O modules (`jobs`, `agents`, `wake`, `runner`); only `macos.js` spawns processes. `cli.js` maps commands onto those modules. Tests run everything on Linux by pointing `WAKECRON_BIN_DIR` at fake macOS tools that record their calls.

**Tech Stack:** Node.js ≥ 20, CommonJS, `node:` built-ins only, `node:test` + `node:assert/strict`.

**Spec:** `docs/superpowers/specs/2026-11-05-wakecron-design.md`

## Global Constraints

- Node.js 20 or newer; CommonJS (`require`, `'use strict'`); no npm dependencies — `node:` built-ins only.
- Runs on macOS only; the test suite (`npm test` = `node --test`) must pass on Linux and macOS.
- Only `lib/macos.js` spawns processes: always an argv array, never a shell string, always `env: ctx.env`.
- Tool paths: launchctl `/bin/launchctl`, pmset `/usr/bin/pmset`, caffeinate `/usr/bin/caffeinate`, osascript `/usr/bin/osascript`, sudo `/usr/bin/sudo`, visudo `/usr/sbin/visudo`, install `/usr/bin/install`, rm `/bin/rm`, bash `/bin/bash`. A non-empty `WAKECRON_BIN_DIR` (tests only) makes every tool except bash `<dir>/<name>`.
- pmset owner string `wakecron`; pmset dates `MM/dd/yy HH:mm:ss`, local time, zero-padded.
- Labels `local.wakecron.<id>`; login agent `local.wakecron.sync`; plists live in `~/Library/LaunchAgents/`.
- Wake lead 60 s; a wake is scheduled only if it is more than 5 s in the future.
- Job ids match `^[a-z0-9][a-z0-9-]{0,40}$` and are never `sync`.
- Exit codes: 0 success, 1 failure, 2 usage error (`UsageError`); `run` exits with the script's exit code (1 when there is none). Errors print as `wakecron: <message>` on stderr.
- Display formats are fixed English (`Fri 06 Nov 07:30`, `2026-11-06 07:30:05`); never `toLocale*`.
- Log rotation at 1048576 bytes, one `.log.1` generation.
- A scheduled one-time run happens only when `at − 2 min ≤ now ≤ at + 24 h`.
- Wake lock: give up after 15 s; a lock is stale when its PID is dead or it is older than 10 minutes.
- Job files and the wake state file are written atomically (temp file + rename).
- Every commit message ends with the attribution trailer lines required by the executing session.

## Review Focus

1. Script paths with spaces inside subfolders (`scripts/Daily Jobs/My Backup.sh`) must schedule as `my-backup-0730` and run — test in Task 9.
2. A project folder path with spaces and `&` (`My Tools & Scripts/`) must be escaped in plists and still run — test in Task 9.
3. Script output with no trailing newline must still leave the end line on its own line — test in Task 8.
4. A script killed by a signal must be recorded as `killed by SIGTERM`, notify, stop caffeinate, and make the runner exit 1 — test in Task 8.
5. Something due within the next minute (`+1m`, a daily time 20 s away) must not schedule a past wake or print `Invalid Date`/`undefined` — tests in Tasks 1 and 9.

test('applyDays', () => {
  assert.deepEqual(s.applyDays({ type: 'repeat', hour: 7, minute: 30 }, undefined), daily(7, 30));

test('nextRun is strictly after now and rolls over weeks, months and years', () => {

### Task 11: sync, setup, uninstall

**Files:**
- Modify: `lib/cli.js`
- Test: `tests/cli-admin.test.js`

**Interfaces:**
- Consumes: `installAgent`, `removeAgent`, `listAgentLabels`, `syncAgentObject`, `jobAgentObject`, `captureEnv` (Task 6); `reconcileWakes`, `cancelAllWakes`, `pmsetMode` (Task 7); `sudoersRule`, `sudoersFileName`, `validateUsername` (Task 3); `macos.sudo/canSudoPmset/failure` (Task 4).
- Produces: the `sync`, `setup` and `uninstall` commands (spec §7.5, §7.6, §7.9).

Full `sync`, in order:
1. Create `scripts/`, `jobs/`, `logs/`, `state/`.
2. For each valid job, set `node`, `root` and `env` from `ctx`, then `writeJob` and `installAgent`.
3. Remove every agent label from `listAgentLabels` that has no job, except `SYNC_LABEL`.
4. If the login agent's plist exists, reinstall it from `syncAgentObject(ctx)`.
5. `reconcileWakes(ctx, { force: true })`.

`--wakes-only` runs only step 5.

Exact text:
- sync: `Synced <n> job(s), removed <m> orphaned agent(s), <k> wake-up(s) scheduled.` Errors → `ctx.warn('Warning: ' + e)` and exit 1. `--wakes-only` prints nothing on success.
- setup:
  - First create `scripts/`, `jobs/`, `logs/`, `state/`.
  - Protected folder (`Desktop`, `Documents`, `Downloads`, `Library/Mobile Documents` under home) → `ctx.warn('Warning: <root> is inside <dir>. macOS blocks background jobs from reading there — move this folder to ~/wakecron.')`.
  - Then `Installing the sudoers rule (sudo may ask for your password)...`.
  - Temp rule file `state/sudoers-<pid>.tmp`, removed in `finally`. `sudo visudo -cf <tmp>` and `sudo install -m 0440 -o root -g wheel <tmp> /etc/sudoers.d/<sudoersFileName>` run with `{ prompt: ctx.interactive }`. A failure throws `macos.failure(...)` (exit 1) and skips the remaining steps.
  - Reset `ctx.cache.sudoPmset`, then print `✓ passwordless wake-ups enabled (/etc/sudoers.d/<file>)` or `✗ sudo doesn't accept the rule yet — check that /etc/sudoers includes /private/etc/sudoers.d`.

  - Run a full sync (its summary line), then print `Setup complete. Try: ./wakecron add hello.sh +3m`.
- uninstall:
  - Order: `cancelAllWakes`, remove every agent label (from `listAgentLabels` plus every job's label), `sudo rm -f /etc/sudoers.d/<file>` (`prompt: ctx.interactive`).
  - Then print `Cancelled <n> wake-up(s), removed <m> agent(s) and the sudoers rule.`
  - Then print `Your scripts, jobs and logs are still in <root>. Delete that folder to remove wakecron completely.`
